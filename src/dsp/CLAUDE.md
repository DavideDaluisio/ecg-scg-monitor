# src/dsp – signal processing

## Where it runs
- All live DSP runs inside `dsp.worker.ts` (Web Worker). Code here must **not** touch the DOM, React or `window`.
- Pure functions/classes (biquad, filter chain, R-peak detector) live in separate files so Vitest can test them directly.
- Transfer `Float32Array` buffers to/from the worker (transferables) instead of copying when possible.

## Units and rates
- Input is in volts at the `fs` of that channel's `SampleBlock` (currently 3000 Hz, but ECG may be 512 Hz on the
  real patch). **Never hard-code 3000.** Coefficients depend on fs, so ECG and SCG chains are designed separately.
- Check that every cutoff is below fs/2 for the channel's fs (the 60 Hz notch and 40 Hz low-pass must also work at 128–512 Hz).
- Recompute coefficients when fs changes.

## Default filter chains (live view, causal)
| Channel | Chain |
|---|---|
| ECG | high-pass 0.5 Hz (baseline wander) → low-pass 40 Hz → notch 60 Hz (US mains) |
| SCG | band-pass 1–30 Hz (configurable) |

- Live filters are **causal IIR biquads** (Direct Form II Transposed, `Float64` state).
- Zero-phase filtering (forward-backward) is allowed only offline (export/analysis), never in the live path.
- Keep raw data untouched. Filtered output goes to separate ring buffers. Recording stores raw samples.

## Validation
- Every filter design is checked against a scipy reference vector in `tests/fixtures/`
  (generated by `tests/fixtures/gen_*.py`). Max absolute error ≤ 1e-4 relative to signal range.
- Use the skill `dsp-filter` to add or change a filter, and ask the `dsp-reviewer` agent to review it.

## Heart rate (M4)
- Simplified Pan-Tompkins on filtered ECG: derivative → square → moving-window integration → adaptive threshold
  with a refractory period of 250 ms.
- Report HR as the median of the last 5 R-R intervals. Report `null` when there are fewer than 2 beats.
- Tested on `SyntheticSource` with a known HR (±1 bpm) and on the real ECG sample.
