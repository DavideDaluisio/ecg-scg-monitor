# Data formats

## Data privacy (read this first)

Real ECG/SCG recordings are **personal health data**. The GitHub Pages site is public, so:

- Real recordings are **never committed and never deployed**. They live only in `public/samples/local/`
  (git-ignored). `vite.config.ts` deletes `dist/samples/local/` after every build, and CI checks it.
- Use neutral ids and file names (`ecg_subject01`), never a person's name.
- Tests use **synthetic** fixtures (`tests/fixtures/`, made by `scripts/make-fixtures.mjs`).
- On the deployed site, users open recordings from their own disk. The file is read in the browser, never uploaded.

## Manifests (`public/samples/manifest.json`, `public/samples/local/manifest.json`)

Lists of recordings shown in the app's picker. The public one is deployed and lists only synthetic or approved data;
the local one is git-ignored and is read only by the dev server (`npm run dev`); production builds never request it.
When it is missing on the dev server, the app ignores it.

```json
{
  "recordings": [
    {
      "id": "ecg_synthetic_demo",
      "file": "ecg_synthetic_demo.lvm",
      "channel": "ecg",
      "fs": 3000,
      "samples": 30000,
      "durationS": 10,
      "simultaneousWith": null
    }
  ]
}
```

- `file` is relative to `public/samples/` (local files: `local/<id>.<ext>`). `channel` is `ecg` or `scg`.
- `fs`, `samples`, `durationS` are informative: the app always computes fs from the file itself.
- `simultaneousWith`: id of a recording made at the same time, or `null`. Malformed entries are skipped.

## Public demo recordings (`public/samples/`, committed, synthetic)

Both are 3000 Hz, 30,000 samples (10 s = exactly 12 beats at 72 bpm, so they loop without a jump), generated by

- `ecg_synthetic_demo.lvm`: ECG, same PQRST and LVM layout as `tests/fixtures/ecg_synthetic.lvm`.
- `scg_synthetic_demo.csv`: SCG, same damped AO/AC bursts and CSV layout as `tests/fixtures/scg_synthetic.csv`.

## Choosing the parser and the channel

`src/io/parseRecording.ts` picks the parser from the file extension (`.lvm`, `.csv`, `.xlsx`, any case); other
extensions fail with a clear message. The channel never comes from the file: manifest entries have `channel`, and
files opened from disk get it from the button the user pressed ("Open ECG file…" / "Open SCG file…").

## LabVIEW `.lvm` (input)

- Text, tab-separated, `.` as decimal separator.
- A file header ends with `***End_of_Header***`. Then a segment header (`Channels`, `Samples`, `Date`, `Time`,
  `Y_Unit_Label`, `X0`, `Delta_X`) ends with another `***End_of_Header***`, followed by the column line
  `X_Value<TAB>Voltage_0<TAB>Comment` and the data rows `time<TAB>value`.
- **Known quirk:** the lab ECG file says `Samples 1000` but contains 72,000 rows. Count the rows, do not trust `Samples`.
- **fs from the time column, not from `Delta_X`:** `0.000333` is a truncated 1/3000, and `1 / 0.000333` = 3003 Hz (wrong).
  Use `fs = round((n − 1) / (t_last − t_first))` over all rows (= 3000 for the lab files). Same rule for CSV and XLSX.
- Files with several segments or several channels: fail with a clear message (not supported yet).

## CSV (input)

Header `time_s,<channel>_V`, one row per sample, `,` as separator, `.` decimal separator.
fs = round((n − 1) / (t_last − t_first)). Parser: `src/io/csv.ts`.

- The header is the first non-empty line when its first cell is not a number (a file without header also works).
  The channel name in it is informative only.
- A leading byte-order mark (Excel) and CRLF line endings are accepted; empty lines are skipped.
- Times may be written without trailing zeros (`0` instead of `0.000000`, as in the lab SCG file).
- Every data row must have exactly 2 numbers, otherwise the parser fails and names the line. This rejects `;`
  separators, `,` decimal separators and multi-column files instead of misreading them.

## XLSX (input)

Read with SheetJS, **lazy-loaded**: the library is a separate chunk (~490 kB) downloaded only when an `.xlsx` file is
opened. Parser: `src/io/xlsx.ts`.

- First sheet only. Column 1 = time (s), column 2 = value (V).
- The header (`Time (s)`, `Voltage (V)` in the lab file) is the first non-empty row when its first cell is not a
  number. Empty rows are skipped.
- A row with a missing or non-numeric time/value, or with a third column, fails with its Excel row number.
  (`scripts/convert-xlsx.mjs` drops such rows instead; the app fails, because raw data must not disappear silently.)

`scripts/convert-xlsx.mjs` converts an `.xlsx` to the CSV format above for `public/samples/local/`.

## CSV export (M4)

When all channels have the same fs:

```
# ecg-scg-monitor export v1
# start_iso=2026-10-06T15:00:00.000Z fs=3000 source=synthetic
sample_index,time_s,ecg_V,scg_V,marker
0,0.000000,1.605213,0.022260,
1,0.000333,1.601534,0.021660,stand up
```

- `time_s = sample_index / fs` (not wall-clock time). Missing samples are empty cells.
- `marker` is non-empty only on the sample where the marker was placed.
- When the channels have **different fs**, one CSV per channel (`<session>_ecg.csv`, `<session>_scg.csv`),
  each with its own `fs`. Never resample: raw stays raw.

## Markers (M4)

`{ channel, sampleIndex, label }` on the reference channel (highest fs, ECG if equal). On export, a marker goes to
`round(t × fs_other)` in the other channels.
